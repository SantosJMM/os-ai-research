# Contribuir

Se aceptan correcciones técnicas, experimentos reproducibles y referencias primarias.

Para proponer una investigación, incluir pregunta, hipótesis, método, entorno, resultados y limitaciones. No incluir secretos, datos personales ni información interna de sistemas reales.

## Normas editoriales para la documentacion publica

- Escribir la documentacion como material tecnico del proyecto: proposito, arquitectura, contratos, ejemplos, decisiones y limitaciones relevantes para lectores y desarrolladores.
- **No insertar metacomentarios del asistente o del proceso de generacion**: no mencionar conversaciones privadas, reconstrucciones realizadas por agentes, limitaciones de acceso al historial, prompts, instrucciones internas o frases como «no es transcripcion literal».
- Si una estructura no esta definida formalmente, identificarla con lenguaje tecnico, por ejemplo: **propuesta**, **borrador**, **ejemplo ilustrativo** o **no normativo**. No presentar esquemas experimentales como contratos aprobados.
- Mantener la trazabilidad tecnica mediante decisiones, versiones y referencias verificables cuando sean utiles, sin convertir los documentos en relatos sobre como fueron redactados.
- Las aclaraciones sobre el trabajo del asistente, sus fuentes internas y sus limitaciones se comunican en la conversacion con quien solicita el cambio, no dentro del README ni de las especificaciones.
- Preservar el contenido y las decisiones del proyecto; evitar correcciones o afirmaciones no verificadas que alteren el significado tecnico.
